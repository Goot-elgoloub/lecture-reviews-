شريحة 02 — Why Dynamic Programming?

المصدر — SOURCE

Some recursive algorithms solve the same subproblems repeatedly, causing unnecessary computations and exponential running time.

  • ❌ Without DP — Solve the same subproblem many times — wasteful and slow.
  • ✔ With DP — Solve once → Store the result → Reuse it when needed.

Learning Objectives: Understand DP motivation, identify overlapping subproblems, explain optimal substructure, and apply Memoization and Tabulation.

شريحة 03 — The Fibonacci Example

المصدر — SOURCE

THE MOTIVATION

The Fibonacci Example

Recursive Definition

F(n) = F(n−1) + F(n−2) (formula image)

Computing F(5) spawns a call tree where F(3) and F(2) are each calculated multiple times — duplicated effort at every level.

💡 The problem is not recursion itself — it is repeated computation.

الصور الأصلية

الصيغة: F(n)=F(n-1)+F(n-2)

قراءة قارئ الشاشة: إف إن تساوي إف إن ناقص واحد زائد إف إن ناقص اثنين.

🖼 إظهار وصف الإتاحة
إتاحة — ACCESSIBILITY

شجرة من أربعة مستويات. في القمة F(5) ويتفرع إلى F(4) على اليسار وF(3) على اليمين. F(4) يتفرع إلى F(3) وF(2). F(3) الأيسر يتفرع إلى F(2) وF(1). F(3) الأيمن يتفرع إلى F(2) وF(1). كل عقدة صندوق ثلاثي الأبعاد ومتصلة بخطوط منقطة.

شريحة 04 — The Problem with Naive Recursion

المصدر — SOURCE

Exponential Time Complexity

T(n) = O(2ⁿ) (formula image)

Each increment of n roughly doubles the number of recursive calls. Computing F(50) naively requires over a quadrillion operations — completely impractical.

📝 Exam Tip: Dynamic Programming is the standard technique for optimizing inefficient recursive solutions.

الصور الأصلية

الصيغة: T(n)=O(2^n)

قراءة قارئ الشاشة: تي إن تساوي أو كبيرة من اثنين أس إن.

شريحة 05 — When Can We Use Dynamic Programming?

المصدر — SOURCE

DP applies only when a problem satisfies both of these properties:

  1. Overlapping Subproblems — The same smaller problems are solved repeatedly. Example: F(5) needs F(3) multiple times.
  2. Optimal Substructure — The optimal solution can be built from optimal solutions of subproblems. Example: shortest path A → C uses optimal sub-paths A → B and B → C.

الشريحة تحتوي صورة زخرفية (تروس) وأيقونتين صغيرتين بلا نص.

شرح جملة بجملة

شرح — EXPLANATION

  1. “DP applies only when a problem satisfies both of these properties”

    DP يُطبَّق فقط عند تحقق الخاصيتين معًا.

  2. “Overlapping Subproblems: The same smaller problems are solved repeatedly. Example: F(5) needs F(3) multiple times.”

    تداخل المسائل: نفس المسائل الأصغر تُحل مرارًا، مثل F(3) داخل F(5).

  3. “Optimal Substructure: The optimal solution can be built from optimal solutions of subproblems. Example: shortest path A → C uses optimal sub-paths A → B and B → C.”

    البنية المثلى: الحل الأمثل يُبنى من حلول مثلى لمسائل فرعية، مثل المسار الأقصر A→C من A→B وB→C.

شرح موسّع

شرح — EXPLANATION
الخاصيتان تعملان معًا: الأولى تعني أن التخزين مفيد، والثانية تعني أن تجميع الحلول الفرعية يعطي الحل الصحيح.
تحدٍّ سريع: هل تكفي خاصية واحدة؟

لا، يجب تحقق الاثنتين.

خلاصة — TAKEAWAY

DP يتطلب Overlapping Subproblems وOptimal Substructure معًا.

شريحة 06 — Overlapping Subproblems

المصدر — SOURCE

PROPERTY 1 — Overlapping Subproblems

Without DP — Repeated Work: F(5) calls F(3) twice and F(2) three times. Each duplicate is a full recomputation.

With DP — Store & Reuse:

  1. 01 Compute F(2) — Store result in table
  2. 02 Compute F(3) — Store result in table
  3. 03 Compute F(4) — Reuse F(2) and F(3) from table

💡 Storage converts repeated computation into a simple table lookup.

شرح جملة بجملة

شرح — EXPLANATION

  1. “Without DP — Repeated Work: F(5) calls F(3) twice and F(2) three times.”

    بدون DP يستدعي F(5) الدالة F(3) مرتين وF(2) ثلاث مرات.

  2. “Each duplicate is a full recomputation.”

    كل تكرار هو إعادة حساب كاملة.

  3. “01 Compute F(2) — Store result in table / 02 Compute F(3) — Store result in table”

    نحسب F(2) ونخزنه، ثم F(3) ونخزنه.

  4. “03 Compute F(4) — Reuse F(2) and F(3) from table”

    نحسب F(4) بإعادة استخدام F(2) وF(3) من الجدول.

  5. “Storage converts repeated computation into a simple table lookup.”

    التخزين يحوّل الحساب المتكرر إلى بحث بسيط في جدول.

شرح موسّع

شرح — EXPLANATION
الجدول يعمل كذاكرة: F(2)=1 وF(3)=2 ثم F(4)=F(3)+F(2). هذه قيم Fibonacci المعيارية (مثال إضافي).
تحدٍّ سريع: بماذا يستبدل DP الحساب المكرر؟

بحث في جدول (lookup).

خلاصة — TAKEAWAY

التداخل يعني حسابًا مكررًا؛ التخزين يحوّله إلى lookup.

شريحة 07 — Optimal Substructure

المصدر — SOURCE

PROPERTY 2 — Optimal Substructure

Definition A problem has optimal substructure if its optimal solution can be constructed from optimal solutions of its subproblems.

Example — Shortest Path: If A → B → C is the shortest path, then A → B and B → C must each be individually optimal.

Overlapping Subproblems saves time. Optimal Substructure makes the solution possible.

شريحة 09 — Memoization

المصدر — SOURCE

TOP-DOWN DP — Memoization

Start with the recursive solution, then store each computed result so it is never recalculated.

  1. Naive Recursion — O(2ⁿ) — exponential, recomputes everything
  2. Add a Cache Table — Check memory before recursing; save each new result
  3. Optimized Solution — O(n) — each subproblem solved exactly once

💡 Memoization = Recursion + Remembering Results

شريحة 10 — Fibonacci with Memoization

المصدر — SOURCE

Algorithm

Fibonacci(n, memo):
  if n <= 1:
    return n
  if n in memo:
    return memo[n]
  memo[n] = Fibonacci(n-1, memo)
            + Fibonacci(n-2, memo)
  return memo[n]

Complexity Analysis

Time: O(n) — Each subproblem computed once

Space: O(n) — Memory table + recursion stack

📝 Exam Tip: Memoization avoids repeated recursive calls by caching results in a table.

شرح الكود سطرًا بسطر

شرح — EXPLANATION
  • Fibonacci(n, memo): — دالة تستقبل n وجدول memo.
  • if n <= 1: return n — الحالة الأساسية: F(0)=0 وF(1)=1 فتُعاد n نفسها.
  • if n in memo: return memo[n] — إن حُسبت القيمة سابقًا نعيدها فورًا دون استدعاءات.
  • memo[n] = Fibonacci(n-1, memo) + Fibonacci(n-2, memo) — نحسب القيمة بالتراجع ونخزنها في memo.
  • return memo[n] — نعيد القيمة المخزنة.

  3. Express T(n): T(n) ≈ c·n (عمل ثابت لكل قيمة).
  4. Simplify: نُسقط الثابت فيبقى O(n).

شريحة 11 — Tabulation: Bottom-Up Dynamic Programming

المصدر — SOURCE

Instead of recursing from the top, tabulation builds the solution from the smallest subproblems upward — iteratively filling a table until the final answer is reached.

Fibonacci Example: Start with F(0)=0, F(1)=1, then compute F(2), F(3), … until F(n).

  1. Solve Small Cases — Initialize base cases directly
  2. Store Results — Cache each computed value in a table
  3. Build Upward — Combine stored values to reach F(n)

💡 Tabulation removes recursion entirely — no stack overhead, just a clean iterative loop.

  2. “Fibonacci Example: Start with F(0)=0, F(1)=1, then compute F(2), F(3), … until F(n).”

    مثال: نبدأ بـ F(0)=0 وF(1)=1 ثم نحسب F(2) وF(3) حتى F(n).

  3. “Solve Small Cases / Store Results / Build Upward”

شريحة 12 — Memoization vs. Tabulation

المصدر — SOURCE

Two strategies, one goal: eliminate redundant computation. Each has distinct trade-offs.

شرح جملة بجملة

شرح — EXPLANATION

  1. “Two strategies, one goal: eliminate redundant computation.”

    استراتيجيتان بهدف واحد: إزالة الحساب الزائد.

  2. “Memoization — Top-Down: uses recursion with a cache; computes states only when needed; requires recursion stack space; natural for tree-like structures”

    Memoization من الأعلى: تراجع مع cache، يحسب الحالات عند الحاجة، يحتاج مساحة مكدس، ومناسب للبنى الشجرية.

  3. “Tabulation — Bottom-Up: uses pure iteration; fills the entire table systematically; no recursion stack — O(1) extra space; ideal when all subproblems are needed”

    Tabulation من الأسفل: تكرار صرف، يملأ الجدول بانتظام، بلا مكدس، ومثالي عندما تلزم كل المسائل الفرعية.

  4. “Time O(n) for both; Memoization space O(n); Tabulation space O(1)”

    الزمن O(n) للطريقتين؛ مساحة memoization هي O(n) ومساحة tabulation هي O(1).

شريحة 13 — The Power of Dynamic Programming

المصدر — SOURCE

DP doesn’t change what you compute — it changes how efficiently you get there.

❌ Before: Naive Recursion

F(n) = F(n−1) + F(n−2)

  • Time: O(2ⁿ) — exponential blowup
  • Same subproblems recomputed millions of times
  • Practically unusable for n > 40

✅ After: Dynamic Programming

  • Store each result once, reuse on demand
  • Time: O(n) — linear improvement
  • Each subproblem solved exactly once
  • Scales to millions of inputs

💡 DP doesn’t change the answer — it changes how efficiently we reach it.

الصيغة: F(n)=F(n-1)+F(n-2)

قراءة قارئ الشاشة: إف إن تساوي إف إن ناقص واحد زائد إف إن ناقص اثنين.

شرح جملة بجملة

شرح — EXPLANATION

  1. “DP doesn’t change what you compute — it changes how efficiently you get there.”

    DP لا يغيّر ما نحسبه بل كفاءة الوصول إليه.

  2. “Before: Time O(2ⁿ) — exponential blowup; same subproblems recomputed millions of times; practically unusable for n > 40”

    قبل: الزمن O(2ⁿ) وانفجار أُسّي وتكرار ملايين المرات، ولا يصلح عمليًا عند n>40.

  3. “After: Store each result once, reuse on demand; Time O(n); each subproblem solved exactly once; scales to millions of inputs”

    بعد: نخزن كل نتيجة مرة ونعيد استخدامها، والزمن O(n)، وتُحل كل مسألة مرة، ويتوسع لملايين المدخلات.

شرح موسّع

شرح — EXPLANATION
الصيغة لم تتغير؛ الذي تغيّر هو التنفيذ. هذا هو معنى "نفس الإجابة بتكلفة أقل".
شرح إضافي — ADDITIONAL

لا، يغيّر الكفاءة فقط.

شريحة 14 — Example: 0/1 Knapsack Problem

المصدر — SOURCE

Given items with weights and values, and a limited capacity — maximize total value without exceeding the weight limit. Each item is either taken or left.

Overlapping Subproblems — The same (item, remaining capacity) states are evaluated repeatedly across different decision paths

Optimal Substructure — The optimal solution builds from optimal solutions to smaller sub-knapsacks

Why DP? Brute force checks 2ⁿ combinations. DP solves it in O(n × capacity) time

شريحة 17 — How to Identify a DP Problem

05 — ثلاثة مستويات

المستويات">

تخيّل أنك تحل واجبًا فيه مسألة تتكرر داخل مسائل أخرى. بدل حلها كل مرة، تكتب جوابها على ورقة جانبية وتنظر إليها عند الحاجة. هذا هو DP: ورقة جانبية (جدول) تحفظ الحلول.

DP يتطلب Overlapping Subproblems وOptimal Substructure. التراجع الساذج لـ Fibonacci يستغرق O(2ⁿ). Memoization (من الأعلى) يحل ذلك بـ cache بزمن O(n) ومساحة O(n)، وTabulation (من الأسفل) بزمن O(n) ومساحة O(1) بعد التحسين. في 0/1 Knapsack تنخفض 2ⁿ إلى O(n × capacity).

  • DP = Solve once → Store → Reuse.
  • Needs: Overlapping Subproblems + Optimal Substructure.
  • Naive Fibonacci: O(2ⁿ) → DP: O(n).
  • Memoization = top-down, recursion + cache, space O(n).
  • Tabulation = bottom-up, iteration, space O(1) optimized.
  • D&C: independent (Solve → Forget). DP: overlapping (Solve → Store → Reuse).
  • Knapsack: 2ⁿ → O(n × capacity).
