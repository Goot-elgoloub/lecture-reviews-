Time & Space Complexity Analysis

مرجع مراجعة تفاعلي — كيف تحدّد بنية الحلقات قيمة Big O، بالإضافة إلى أفضل/متوسط/أسوأ الحالات، ودراسات حالة لخوارزميات ترتيب كلاسيكية، والوجه الآخر للقصة: تعقيد المساحة (Space Complexity).

01 / OVERVIEW

نظرة عامة على المحاضرة

المحاضرة الثالثة تبني مباشرة على مفهوم Big O من المحاضرة الثانية. تتعمّق في كيفية إنتاج بنيات الحلقات المختلفة (متتالية، متداخلة، معتمدة، لوغاريتمية، مختلطة) لمعدلات نمو مختلفة، وتقدّم تحليل أفضل/متوسط/أسوأ الحالات، ثم تطبّق كل ذلك على خمس دراسات حالة لخوارزميات حقيقية، وأخيرًا تفتح بُعدًا جديدًا: تعقيد المساحة (Space Complexity) — كمية الذاكرة التي تحتاجها الخوارزمية، وليس فقط الزمن.

🎯 الفكرة المحورية

ليست كل المدخلات متساوية. نفس الخوارزمية قد تتصرف بشكل مختلف تمامًا حسب المدخل الذي تستقبله — لهذا نميّز بين أفضل حالة ومتوسط حالة وأسوأ حالة. وبعيدًا عن الزمن، لكل خوارزمية أيضًا بصمة ذاكرة — تعقيد المساحة (Space Complexity) — يجب قياسها بنفس الدقة التي نقيس بها الزمن.

02 / FULL EXPLANATION

الشرح الكامل لكل قسم في المحاضرة

كل بطاقة تغطي جزءًا من المحاضرة بالترتيب، دون تجاوز أي معلومة واردة في الشرائح.

3.1 مراجعة: حل التحدي 1 — تحليل حلقة بسيطة

تفتتح المحاضرة بمراجعة تحدي المحاضرة الثانية، مطبّقة عليه خطوات التحليل الأربع:

for (i = 1; i <= n; i++) {
    print(i);
}
Basic Operation

print(i)

Executions

n مرة

Running Time

T(n) = n

Time Complexity

O(n) — خطي

جسم الحلقة يُنفَّذ مرة واحدة لكل قيمة من i، مما ينتج نموًا خطيًا.

3.2 تحليل أفضل ومتوسط وأسوأ الحالات

نفس الخوارزمية بالضبط قد تحتاج عددًا مختلفًا من العمليات حسب المدخل المحدد الذي تستقبله — لذلك نصف الأداء عبر ثلاثة سيناريوهات:

الحالةالمعنى
Best Caseالحد الأدنى من العمليات المطلوبة — أفضل مدخل ممكن.
Average Caseالعدد المتوقع من العمليات عبر مدخلات عشوائية نموذجية.
Worst Caseالحد الأقصى من العمليات — أكثر مدخل إرهاقًا. هذا هو التركيز القياسي في تحليل الخوارزميات.

3.3 الحلقات المتداخلة المعتمدة (Dependent Nested Loops)

أحيانًا يعتمد مدى الحلقة الداخلية على متغيّر الحلقة الخارجية الحالي، وليس على n مباشرة:

for i = 1 to n
    for j = 1 to i
        operation
مفتاح
تكرارات الحلقة الداخلية تعتمد على قيمة i — عندما i=1 تعمل الحلقة الداخلية مرة واحدة، وعندما i=2 تعمل مرتين، وهكذا حتى i=n تعمل n مرة.
Number of Operations

1 + 2 + 3 + ... + n = n(n+1) / 2

Time Complexity

O(n²)

مثال رقمي (n=4): تعمل الحلقة الداخلية 1+2+3+4 = 10 مرات إجمالًا — وهو ما يطابق n(n+1)/2 = 4×5/2 = 10.

3.4 الحلقات المتداخلة المعتمدة العكسية (Reverse Dependent)

for (i = 1; i <= n; i++)
    for (j = i; j <= n; j++)
        operation;

هنا تعمل الحلقة الداخلية n، n-1، n-2، …، 1 مرة — الترتيب معكوس مقارنة بالمثال السابق، لكن المجموع الكلي نفسه.

n + (n-1) + ... + 1 = n(n+1)/2 = O(n²)

الخلاصة المهمة: بنيات حلقات مختلفة يمكن أن تنتج نفس التعقيد المقارب تمامًا — اتجاه العدّ لا يغيّر رتبة النمو.

3.5 التعقيد بمتغيّرين (تحليل متعدد المتغيرات)

for (i = 1; i <= n; i++)
    for (j = 1; j <= m; j++)
        operation;
Operations

n * m

Complexity

O(nm)

قاعدة أساسية: n و m هما حجما مدخل مستقلان. لا تستبدل m بـ n تلقائيًا أبدًا — فقد يمثّلان كميتين مختلفتين تمامًا (مثل صفوف وأعمدة مصفوفتين مختلفتين).

3.6 الحلقات اللوغاريتمية (Logarithmic Loops)

while (n > 1) {
    n = n / 2;
}

تقليص المسألة بشكل متكرر بعامل ثابت (هنا القسمة على 2 كل مرة) ينتج نموًا لوغاريتميًا — لأن عدد المرات التي يمكن فيها تنصيف n قبل الوصول إلى 1 هو log₂(n).

مثال رقمي: البدء من n=16 → 8 → 4 → 2 → 1 يستغرق بالضبط 4 خطوات = log₂(16). مضاعفة n إلى 32 تضيف خطوة واحدة فقط (5 خطوات) — وهذا ما يجعل الخوارزميات اللوغاريتمية فعّالة جدًا عند النطاق الكبير.

O(log n)

3.7 الحلقات الثلاثية المتداخلة (Triple Nested Loops)

for (i = 1; i <= n; i++)
    for (j = 1; j <= n; j++)
        for (k = 1; k <= n; k++)
            operation;
Operation Count

n × n × n = n³

Time Complexity

O(n³) — Cubic

مبدأ أساسي: الحلقات المتداخلة تضرب عدد مرات تنفيذها — مع ثلاثة مستويات من التداخل، نضرب ثلاث مرات.

3.8 تحليل الحلقات المختلطة — O(n log n)

for i = 1 to n
    j = 1
    while j < n
        operation
        j = j × 2
Outer Loop

تعمل n مرة ← O(n)

Inner Loop

j تتضاعف كل مرة ← O(log n)

مجتمعة

n × log n = O(n log n)

حلقة خارجية خطية مقترنة بحلقة داخلية لوغاريتمية نمط شائع جدًا — تذكّر: متداخلة ← اضرب، فـ O(n) × O(log n) = O(n log n).

3.9 التعرّف على أنماط التعقيد

نمط الكودالتعقيد
جملة واحدةO(1)
حلقة واحدةO(n)
حلقتان متداخلتانO(n²)
ثلاث حلقات متداخلةO(n³)
القسمة على 2 كل تكرارO(log n)
حلقة خطية + لوغاريتميةO(n log n)
تذكّر: احسب دائمًا عدد التنفيذات قبل تحديد التعقيد. هذه الأنماط أدلة إرشادية، وليست بديلًا عن التحليل الفعلي.

3.10 دراسة حالة 1 — تحليل Bubble Sort

في كل تمريرة، تُقارن العناصر المتجاورة بشكل متكرر. إجمالي عدد المقارنات يشكّل متسلسلة حسابية:

(n-1) + (n-2) + ... + 2 + 1 = n(n-1)/2 = O(n²)
الحالةالتعقيد
Best*O(n)
متوسطO(n²)
أسوأO(n²)

* مع التحسين (الإيقاف المبكر عند مصفوفة مرتبة أصلًا).

3.11 دراسة حالة 2 — تحليل Merge Sort

يستخدم Merge Sort مبدأ فرّق تسد (divide and conquer): قسّم المصفوفة إلى نصفين، حلّ كل نصف بشكل تكراري (recursive)، ثم ادمج النصفين المرتبين.

Divide
Conquer
Merge

T(n) = 2T(n/2) + n

العمل لكل مستوى: n · عدد المستويات: log₂ n

n × log n = O(n log n)

الحالةالتعقيد
أفضلO(n log n)
متوسطO(n log n)
أسوأO(n log n)

3.12 دراسة حالة 3 — تحليل Quick Sort

الحالةالتعقيدلماذا
أفضلO(n log n)تقسيمات متوازنة عند كل مستوى
متوسطO(n log n)المحاور العشوائية تعطي تقسيمات متوازنة

3.13 دراسة حالة 4 — شجرة البحث الثنائية (تعقيد البحث حسب نوع الشجرة)

نوع الشجرةالتعقيد
شجرة متوازنةO(log n)
شجرة غير متوازنةO(n)

الشجرة المتوازنة تُنصّف مساحة البحث في كل خطوة (تمامًا مثل البحث الثنائي في مصفوفة مرتبة). أما الشجرة غير المتوازنة بشدة فتتحول فعليًا إلى ما يشبه القائمة المترابطة (linked list) — البنية هي كل شيء.

3.14 دراسة حالة 5 — اجتياز الرسوم البيانية (Graph Traversal)

Breadth-First Search (BFS)

O(V + E)

يستكشف كل الجيران عند كل عمق قبل التعمّق أكثر.

Depth-First Search (DFS)

O(V + E)

يتبع كل فرع حتى نهايته قبل التراجع (backtracking).

V = عدد الرؤوس (vertices)، E = عدد الأضلاع (edges). التعقيد هنا يعتمد على معاملين للمدخل — وليس فقط n واحدة.

3.15 أخطاء شائعة في تحليل تعقيد الزمن

❌
الخطأ 1 — حلقتان لا تعني بالضرورة O(n²)

حلقات متتالية ← O(n)  |  حلقات متداخلة ← O(n²)

❌
الخطأ 2 — تجاهل السلوك اللوغاريتمي

معاملة التنصيف المتكرر كأنه خطي (خطأ)  |  القسمة/الضرب في ثابت ← O(log n) (صحيح)

❌
الخطأ 3 — الخلط بين O(n+m) و O(nm)

O(n+m) = جمعي (متتالي)  |  O(nm) = متداخل / ضربي

3.16 قائمة تحقق لتحليل الخوارزميات (المنهجية)

قبل كتابة Big O النهائي، اعمل على هذه الأسئلة الخمسة بالترتيب:

#الخطوةالسؤال الموجّه
01حدّد العملية الأساسيةما هي الخطوة الجوهرية التي يتم عدّها؟
02عدّ التنفيذاتكم مرة تُنفَّذ كدالة في حجم المدخل؟
03عبّر عنها كـ T(n)اكتب عدد التنفيذات كتعبير رياضي.
04أوجد الحد المهيمنأي حد ينمو أسرع عندما n → ∞؟
05بسّط واكتب Big Oأسقط الثوابت والحدود الأقل رتبة.
استراتيجية الامتحان: عُدّ أولًا. بسّط ثانيًا. لا تخمّن Big O من مظهر الكود فقط أبدًا.

3.17 تحدٍ سريع + كيفية حلّه

حدّد تعقيد الزمن لبنية الحلقات المتداخلة التالية:

for (i = 1; i <= n; i++) {
    j = 1;
    while (j <= n) {
        operation;
        j = j * 2;
    }
}

إطار مقترح من 4 خطوات لحلّه بنفسك قبل قراءة الإجابة:

  1. حلّل الحلقة الخارجية — كم تكرارًا تنفّذ i؟
  2. حلّل الحلقة الداخلية — كيف تتغيّر j في كل تكرار؟
  3. حدّد سلوك الحلقة — هل هي خطية أم لوغاريتمية أم شيء آخر؟
  4. ادمج النتائج — اضرب الحلقات المتداخلة؛ اجمع المتتالية.
Outer Loop

تعمل n مرة — تكرار خطي

Inner Loop

j تتضاعف كل خطوة — لوغاريتمي

مجتمعة

n × log n

الإجابة: O(n log n) — الحلقة الخارجية تعمل n مرة، والحلقة الداخلية تعمل log₂ n مرة لكل تكرار خارجي. هذا النمط (خارجية خطية + داخلية لوغاريتمية) يظهر بكثرة في مسائل التعقيد.

3.18 مقدمة في تعقيد المساحة (Space Complexity)

لكفاءة الخوارزمية بُعدان — كلاهما مهم عمليًا:

⏱️ تعقيد الزمن

كم من العمل الحسابي تؤديه الخوارزمية؟

💾 تعقيد المساحة

كم من الذاكرة تحتاجها الخوارزمية أثناء التنفيذ؟

تعقيد المساحة يأخذ بعين الاعتبار تخزين المدخل وأي ذاكرة إضافية تُخصَّص أثناء التشغيل. الخوارزميات الفعّالة يجب أن توازن بين الزمن والذاكرة معًا.

3.19 ثلاثة أنواع من المساحة

عند تحليل الخوارزميات، يجب أخذ استخدام الذاكرة بعين الاعتبار — وليس فقط الزمن. ثلاثة مفاهيم متمايزة تحدد هذا القياس:

Input Space

الذاكرة المطلوبة لتخزين بيانات المدخل.

O(n)

لمصفوفة من n عنصر

Auxiliary Space

الذاكرة الإضافية المستخدمة أثناء التنفيذ.

O(1)

عند استخدام بضعة متغيرات إضافية فقط

Total Space

Input Space + Auxiliary Space

O(n)

في مثال المصفوفة أعلاه

فكرة أساسية: عند مقارنة الخوارزميات، ميّز دائمًا بين تخزين المدخل والذاكرة الإضافية (auxiliary) — خوارزميتان بنفس Input Space قد يكون لهما Auxiliary Space مختلف جدًا.
03 / DIAGRAMS & CHARTS

شرح الرسومات والمخططات

وصف دقيق لكل رسم ورد في المحاضرة، مرتبط بالمفهوم النظري خلفه.

🔁 مخطط 1 — الحلقات المتداخلة المعتمدة العكسية

Row Diagram

يُصوّر هذا المخطط الكود for i=1..n: for j=i..n كسلسلة من الصفوف الأفقية، صف واحد لكل قيمة من i، كل صف مكوّن من مربعات صغيرة متصلة (□ — □ — □ ...) تمثّل تكرارات الحلقة الداخلية:

i = 1···(n مربع — أطول صف)
i = 2···(n-1 مربع)
i = 3···(n-2 مربع)
⋮⋮
i = n(مربع واحد — أقصر صف)

كل صف موسوم بسهم يوضّح ما يمثّله: الصف العلوي (i=1) موسوم بـ "الحلقة الخارجية i من 1 إلى n"، والصفوف التالية موسومة بـ "الحلقة الداخلية j من i إلى n"، ونمط التقلّص موسوم بـ "تكرارات الحلقة الداخلية تتناقص n، n-1، …، 1". وفي الأسفل توضيح للمجموع الكلي: n(n+1)/2 = O(n²) — وهو يطابق تمامًا الصيغة المُشتقة من الكود.

قراءة الشكل: الصفوف تشكّل درجًا/مثلثًا متقلّصًا — عريض من الأعلى (i=1، n مربع) وضيق من الأسفل (i=n، مربع واحد). هذا الشكل المثلثي هو "بصمة بصرية" لـ O(n²): جمع 1+2+...+n (أو n+(n-1)+...+1، نفس المجموع) يعطي دائمًا نمط "الأعداد المثلثية".

🧊 مخطط 2 (مفاهيمي) — الحلقات الثلاثية المتداخلة كمكعب

3D Grid

توضّح الشريحة التداخل الثلاثي بمكعب فني ثلاثي الأبعاد مكوّن من شبكة عُقد متوهجة متصلة عبر الأبعاد الثلاثة. من الناحية المفاهيمية: الحلقة الواحدة هي خط من n نقطة، والحلقتان المتداخلتان شبكة مستوية من n×n نقطة (مربع)، والحلقات الثلاث المتداخلة تمدّد هذا إلى مكعب من n×n×n نقطة — نقطة واحدة لكل تركيبة من (i, j, k). عدّ كل عقدة في هذا المكعب يعطي بالضبط n³ عملية، مما يفسّر بصريًا لماذا تنتج ثلاثة مستويات من التداخل نموًا تكعيبيًا.

🔀 مخطط 3 — Merge Sort: تقسيم ← حل ← دمج

Process Flow

ثلاث أيقونات دائرية متداخلة ومتصلة في سلسلة أفقية تمثّل مراحل Merge Sort الثلاث بالترتيب:

↝
1. تقسيم (Divide)

الأيقونة: سهم متفرّع — المصفوفة تنقسم إلى نصفين.

↻
2. حل (Conquer)

الأيقونة: سهم دائري تكراري — كل نصف يُحل بشكل تكراري (نفس العملية تتكرر على أجزاء أصغر).

⤞
3. دمج (Merge)

الأيقونة: أسهم متقاربة — النصفان المرتبان يُدمجان مرة أخرى في مصفوفة واحدة مرتبة.

أسفل الأيقونات الثلاث، تضع الشريحة علاقة التكرار T(n) = 2T(n/2) + n جنبًا إلى جنب مع جدول صغير يوضّح أن أفضل/متوسط/أسوأ الحالات كلها تساوي O(n log n) — مما يعزّز بصريًا أن أداء Merge Sort لا يعتمد على الترتيب الأولي للمدخل، على عكس Bubble Sort أو Quick Sort.

📐 مخطط 4 (مفاهيمي) — بُعدان مستقلان n و m

Two Grids

تعرض الشريحة ورقتي شبكة مرسومتين يدويًا بحجمين مختلفين ومتداخلتين جزئيًا، إحداهما موسومة على حافتها بـ n والأخرى بـ m، ومائلتان بزوايا مختلفة للتأكيد على أنهما شبكتان منفصلتان ومستقلتان وليستا شبكة مربعة واحدة. هذا يعزّز بصريًا نص "القاعدة الأساسية" المجاور: n و m حجما مدخل مستقلان يظهران معًا في نفس الحلقة المتداخلة، ويجب ألا يُفترض تساويهما أو يُستبدل أحدهما بالآخر تلقائيًا.

04 / SUMMARY

تلخيص شامل — المفاهيم والتعريفات الجوهرية

المصطلحالتعريف
Best Caseالحد الأدنى من العمليات — أفضل مدخل ممكن.
Average Caseالعدد المتوقع من العمليات عبر مدخلات عشوائية نموذجية.
Worst Caseالحد الأقصى من العمليات — التركيز القياسي في التحليل.
Dependent Nested Loopsمدى الحلقة الداخلية يعتمد على المتغيّر الخارجي (مثل j=1 إلى i) ← O(n²).
Reverse Dependent Nested Loopsنفس المجموع الكلي للحلقات المعتمدة، لكن معدودة عكسيًا (n، n-1، ...، 1) ← O(n²).
O(nm)التعقيد بمتغيّري مدخل مستقلّين n و m.
O(log n)ناتج عن تقليص المسألة بشكل متكرر بعامل ثابت (مثل n = n/2).
O(n³)حلقات ثلاثية متداخلة — ثلاثة مستويات تُضرب: n × n × n.
O(n log n)حلقة خطية مقترنة بحلقة لوغاريتمية (مضروبتان، لأنهما متداخلتان).
Bubble Sortأفضل O(n)* / متوسط O(n²) / أسوأ O(n²). *مع تحسين الإيقاف المبكر.
Merge Sortأفضل = متوسط = أسوأ = O(n log n). علاقة التكرار: T(n) = 2T(n/2) + n.
Quick Sortأفضل/متوسط O(n log n)؛ أسوأ O(n²) مع محور سيء.
Balanced vs Unbalanced BSTمتوازنة O(log n) مقابل غير متوازنة O(n) (تتحول إلى ما يشبه القائمة المترابطة).
BFS / DFSكلاهما O(V + E) — يعتمد على الرؤوس V والأضلاع E، وليس n واحدة.
Input Spaceالذاكرة لتخزين المدخل — O(n) لمصفوفة من n عنصر.
Auxiliary Spaceالذاكرة الإضافية أثناء التنفيذ — O(1) عند استخدام بضعة متغيرات إضافية فقط.
Total SpaceInput Space + Auxiliary Space.
05 / THREE LEVELS

تبسيط على 3 مستويات

تخيّل ترتيب مجموعة أوراق لعب (deck of cards):

  • أفضل/متوسط/أسوأ حالة مثل أن تسأل: كم يستغرق إيجاد ورقة معينة؟ لو الأوراق مرتبة مسبقًا، الأمر فوري (أفضل حالة). لو مخلوطة عشوائيًا، يستغرق مجهودًا نموذجيًا (متوسط حالة). لو مرتبة بالعكس تمامًا — أسوأ ترتيب ممكن لطريقتك — يستغرق أطول وقت (أسوأ حالة).
  • الحلقات المتداخلة المعتمدة مثل مقارنة كل ورقة بكل الأوراق التي تسبقها — الورقة الأولى لا تقارن بشيء، الثانية تقارن بواحدة، الثالثة باثنتين، وهكذا — والعبء الكلي ينتهي به الأمر تربيعيًا.
  • الحلقات اللوغاريتمية مثل تخمين رقم بين 1 و1000 عن طريق تنصيف المدى دائمًا — تجده خلال حوالي 10 محاولات، وليس 1000.
  • تعقيد المساحة ببساطة: كم يجب أن تكون الطاولة كبيرة لتفرد عليها أوراقك؟ مجموعة أوراق أكبر (المدخل) تحتاج طاولة أكبر (Input Space)؛ احتياجك لكومة صغيرة إضافية تساعدك في الترتيب هو Auxiliary Space.

تُوسّع هذه المحاضرة منهجية التحليل بأربع خطوات من المحاضرة الثانية لتشمل بنيات حلقات أكثر تعقيدًا. مهارتان تشغيليتان أساسيتان تهمّان أكثر من غيرهما:

  • عندما يعتمد حد الحلقة الداخلية على المتغيّر الخارجي (مثل j = 1 to i)، لا يمكنك ببساطة ضرب n × n. بدلًا من ذلك يجب جمع التسلسل الفعلي لأطوال الحلقة الداخلية (1 + 2 + ... + n)، والذي يؤول إلى صيغة المتسلسلة الحسابية n(n+1)/2 — تبقى O(n²)، لكن مُشتقّة وليست مفترضة.
  • تحليل أفضل/متوسط/أسوأ حالة مهم لأن تعبير Big O واحد قد يخفي سلوكيات مختلفة جدًا: Quick Sort هو O(n log n) في المتوسط لكنه يتدهور إلى O(n²) في أسوأ الحالات إذا كان اختيار المحور (pivot) سيئًا، بينما Merge Sort يضمن O(n log n) في كل الحالات لأن خطوة التقسيم فيه متوازنة دائمًا بغض النظر عن المدخل.

تعقيد المساحة يُحلَّل بنفس الدقة التي يُحلَّل بها الزمن: Input Space يأخذ بعين الاعتبار الذاكرة اللازمة لحمل المدخل نفسه (عادة O(n))، بينما Auxiliary Space يأخذ بعين الاعتبار أي ذاكرة إضافية تُخصّصها الخوارزمية بعيدًا عن المدخل — مكدسات الاستدعاء التكراري (recursive call stacks)، أو مصفوفات مؤقتة، أو مؤشرات إضافية. خوارزمية ترتب في المكان (in place) باستخدام عدد ثابت فقط من المتغيرات الإضافية لها Auxiliary Space يساوي O(1)، حتى لو كان تعقيد زمنها O(n²) أو O(n log n)؛ يُقاس البُعدان بشكل مستقل.

  • Best case = min ops. Average = expected ops. Worst = max ops (standard focus).
  • Dependent nested: j=1..i → 1+2+...+n = n(n+1)/2 → O(n²).
  • Reverse dependent: j=i..n → n+(n-1)+...+1 = same total → O(n²).
  • Two variables: for i..n, for j..m → operations = n*m → O(nm). Never assume n=m.
  • Logarithmic: n = n/2 repeatedly → O(log n).
  • Triple nested loop → n × n × n = n³ → O(n³).
  • Linear outer + logarithmic inner (nested → multiply) → O(n) × O(log n) = O(n log n).
  • Bubble Sort: Best O(n)* / Avg O(n²) / Worst O(n²).
  • Merge Sort: Best = Avg = Worst = O(n log n). T(n) = 2T(n/2) + n.
  • Quick Sort: Best/Avg O(n log n); Worst O(n²) (bad pivot).
  • Balanced BST O(log n); Unbalanced BST O(n).
  • BFS = DFS = O(V + E).
  • Mistake check: sequential loops ADD (O(n+m)); nested loops MULTIPLY (O(nm)).
  • 5-step checklist: Identify → Count → Express T(n) → Find dominant term → Simplify.
  • Space: Input Space O(n) + Auxiliary Space (often O(1)) = Total Space.

مراجعة أخيرة مركّزة فقط على:

  • الأخطاء الشائعة الثلاثة (متتالية مقابل متداخلة، لوغاريتمي مقابل خطي، O(n+m) مقابل O(nm))

08 / PRO TIPS

نصائح احترافية

💡 كيف تفهم بدلًا من الحفظ

🔍
لا تحفظ "Quick Sort هو O(n log n)" كحقيقة مطلقة — افهم أن هذا فقط في المتوسط/أفضل حالة، وأن أسوأ حالة تعتمد كليًا على اختيار المحور (pivot).
✍️
في الحلقات المتداخلة المعتمدة، اكتب دائمًا التسلسل الفعلي لعدّادات الحلقة الداخلية (1،2،3،...،n) قبل القفز إلى صيغة n(n+1)/2 — هذا يمنع الأخطاء الميكانيكية.
📐
افصل تمامًا في ذهنك بين السؤالين "كم من الزمن؟" و"كم من الذاكرة؟" — الخوارزمية قد تكون سريعة لكنها شرهة للذاكرة (أو العكس)، وأسئلة الامتحان غالبًا ما تختبر هذا التمييز بالذات.

🏋️ تدريب عملي مقترح

1️⃣
تتبّع Bubble Sort يدويًا على مصفوفة صغيرة من 5 عناصر في أسوأ حالة (مرتبة عكسيًا) واعدّ كل مقارنة — تحقق من أنها تطابق n(n-1)/2.
2️⃣
اكتب 3 مقاطع كود بنفسك: واحد بحلقات متتالية (O(n+m))، وآخر بحلقات متداخلة (O(nm))، وقارن عدد عملياتهما لنفس القيم الصغيرة لـ n و m.
3️⃣
ارسم شجرة BST متوازنة وأخرى غير متوازنة بنفس 7 قيم، واعدّ يدويًا خطوات البحث عن نفس القيمة الهدف في كلتيهما لتشعر بالفرق بين O(log n) و O(n).

⚠️ أخطاء شائعة يقع فيها الطلاب في هذا الموضوع تحديدًا

❌
افتراض أن حلقتين تعنيان دائمًا O(n²): هذا صحيح فقط للحلقات المتداخلة. حلقتان متتاليتان (متتابعتان) كل واحدة بحجم n هما O(n) + O(n) = O(n)، وليس O(n²).
❌
معاملة التنصيف المتكرر كأنه خطي: حلقة مثل while(n>1) n=n/2 تبدو وكأنها تعمل "كثيرًا"، لكنها O(log n)، وليست O(n) — عُدّ عدد التنصيفات الفعلي، لا تخمّن.
❌
الخلط بين O(n+m) و O(nm): إذا كانت حلقتان بمتغيّرين مختلفين تعملان واحدة بعد الأخرى، اجمعهما (O(n+m))؛ وإذا كانت إحداهما متداخلة داخل الأخرى، اضربهما (O(nm)). الخلط بينهما من أكثر أخطاء الامتحانات شيوعًا.
❌
ذكر Big O واحد لخوارزمية دون تحديد الحالة: قول "Quick Sort هو O(n log n)" دون ذكر أن هذا في أفضل/متوسط الحالة (وليس أسوأها) إجابة ناقصة — وغالبًا ما تُخصم عليها درجات.
❌
نسيان قياس تعقيد المساحة بمعزل عن الزمن: بعض الطلاب يفترضون أن الخوارزمية السريعة تستخدم بالضرورة ذاكرة قليلة (أو العكس) — قيّم دائمًا Input Space و Auxiliary Space بشكل مستقل.
