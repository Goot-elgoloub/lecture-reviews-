Recurrence Relations

مرجع مراجعة تفاعلي — كيف نُشكِّل نموذجًا رياضيًا لتكلفة خوارزمية تكرارية-ذاتية، وحلّ علاقات التكرار بالتوسيع والاستبدال، وقراءة التعبيرات المقاربة، وتطبيق حالات نظرية Master الثلاث.

نظرة عامة الشرح الكامل الرسومات والمخططات جدول التلخيص 3 مستويات الاختبار التفاعلي نصائح احترافية
01 / OVERVIEW

نظرة عامة على المحاضرة

تجيب المحاضرة السادسة على السؤال الذي تركته Divide and Conquer مفتوحًا: إذا استدعت خوارزمية نفسها، كيف نحسب زمن تشغيلها رياضيًا؟ تُقدّم علاقات التكرار (recurrence relations) كنموذج تكلفة، وتحلّها بالتوسيع وبالاستبدال، وتُراجع الترميز المقارب (الحد المهيمن، Big O مقابل Big Theta، مقارنة معدلات النمو)، وتبني علاقة تكرار Merge Sort وشجرة استدعائها، وتختتم بنظرية Master — اختصار بثلاث حالات لحل علاقات تكرار فرّق تسد دون توسيع خطوة بخطوة.

🎯 الفكرة المحورية

علاقة التكرار نموذج رياضي لتكلفة خوارزمية — تصف زمن تشغيل خوارزمية تكرارية-ذاتية بدلالة زمن التشغيل على مدخلات أصغر. بمجرد أن تستطيع كتابة علاقة التكرار، لديك ثلاث أدوات لحلّها: توسيعها مستوى بمستوى، تخمينها وإثباتها بالاستبدال، أو — لشكل فرّق تسد الشائع — تصنيفها فوريًا بنظرية Master.

🧠 أهم المفاهيم في هذه المحاضرة

  • المكوّنات الثلاثة لعلاقة التكرار: الجزء التكراري، العمل الخارجي، الحالة الأساسية
  • الحل بالتوسيع (مستوى بمستوى) وبالاستبدال (تخمين ← استبدال ← إثبات)
  • الحدود المهيمنة، Big O (الحد الأعلى) مقابل Big Theta (الحد المُحكَم)
  • ترتيب معدلات النمو: log n < n < n log n < n² < n³ < 2ⁿ
  • طريقة شجرة الاستدعاء مُطبَّقة على Merge Sort
  • الصيغة العامة لنظرية Master وحالاتها الثلاث

02 / FULL EXPLANATION

الشرح الكامل لكل قسم

كل بطاقة تغطي جزءًا من المحاضرة بالترتيب، دون تجاوز أي معلومة من الشرائح.

6.1 أين توقفنا — وإلى أين نتجه

المحاضرة السابقة

استكشفنا Divide and Conquer كاستراتيجية تصميم — تقسيم المسائل إلى مسائل فرعية أصغر، حلّ كل منها تكراريًا، ثم دمج النتائج.

تركيز اليوم

كيف نُحلّل الخوارزميات التكرارية-ذاتية رياضيًا؟ إذا استدعت خوارزمية نفسها، كيف نحسب زمن تشغيلها؟

أهداف التعلّم: فهم علاقات التكرار · بناء معادلات تكرار من الخوارزميات · حلّ علاقات تكرار بسيطة · تطبيق نظرية Master.

6.2 ما هي علاقة التكرار؟

علاقة التكرار تصف زمن تشغيل خوارزمية بدلالة أحجام مدخلات أصغر — نموذج رياضي للبنية التكرارية-الذاتية.

علاقة التكرار نموذج رياضي لتكلفة خوارزمية.

مثال — Binary Search:

6.3 مكوّنات علاقة التكرار

لكل علاقة تكرار ثلاثة أجزاء تصف معًا تكلفة الخوارزمية كاملة.

#الجزءالصيغةالوصف

6.4 حلّ علاقة تكرار بسيطة (طريقة التوسيع)

اعتبر T(n) = T(n/2) + c. كل توسيع يُضيف مستوى عمل آخر:

Level 1:  T(n) = T(n/2) + c
Level 2:  T(n) = T(n/4) + 2c
Level 3:  T(n) = T(n/8) + 3c
...
After k levels:  T(n) = T(n/2^k) + kc
يتوقف الاستدعاء-الذاتي عندما n/2ᵏ = 1، إذن k = log₂ n. النتيجة: T(n) = Θ(log n). القسمة المتكررة على 2 تُنتج عمقًا لوغاريتميًا.

6.5 تحديد الحد المهيمن

لأي تعبير متعدد حدود أو مقارب، ركّز على الحد الذي ينمو الأسرع مع n → ∞. الحدود الأدنى رتبة والثوابت تصبح غير ذات أهمية.

T(n) = 4n³ + 2n² + n + 1n³Θ(n³)
T(n) = n log₂ n + 10nn log nΘ(n log n)

6.7 Big O مقابل Big Theta

الترميزالاسمالمعنى
f(n) = O(g(n))Big O — الحد الأعلىf(n) لا تنمو أسرع من g(n). إنه سقف — لن تستغرق الخوارزمية أطول من هذا.
f(n) = Θ(g(n))Big Theta — الحد المُحكَمf(n) وg(n) تتشاركان نفس معدل النمو المقارب. إنه توصيف دقيق.
نصيحة امتحان: n = O(n²) صحيحة، لكن n = Θ(n²) خاطئة. الوصف الأدق هو n = Θ(n). حد Big O قد يكون صحيحًا دون أن يكون الأدق.

6.8 تدريب سريع على التحليل المقارب

قبل الحل، اسأل نفسك: هل لديّ تعبير جاهز، أم أحتاج لبناء علاقة تكرار؟

السؤالالحد المهيمنالإجابة

f(n) = 3n² + 7n + 1n²Θ(n²)
f(n) = 7n³ + 100n² + 5000n³Θ(n³)

6.9 مقارنة معدلات النمو

مع n → ∞، معدل النمو هو كل شيء. قد تكون دالة أكبر عند مدخلات صغيرة لكنها تُهيمَن عليها في النهاية بدالة أسرع نموًا.

مثال: n² = O(2ⁿ) ✓ لكن 2ⁿ ≠ O(n²) ✗ — الأسّي يُهيمن على كثير الحدود.
ترتيب النمو: log n < n < n log n < n² < n³ < 2ⁿ

6.10 Big O و Big Theta — صح أم خطأ؟

العبارةالإجابةلماذا
n ∈ O(n²)✓ صحالحد الأعلى يصمد.
n² ∈ O(n²)✓ صحنفس معدل النمو.
n² ∈ O(n)✗ خطأn² تنمو أسرع.
log n ∈ O(n)✓ صحاللوغاريتم أبطأ.
n² ∈ Θ(n)✗ خطأليس حدًا مُحكَمًا.
تذكّر: Big O ← حد أعلى. Big Θ ← حد مُحكَم. قد تكون عبارة صحيحة بـBig O دون أن تكون الوصف الأدق.

6.11 علاقة تكرار Merge Sort

يتبع Merge Sort نمط Divide and Conquer بالضبط، مُنتجًا علاقة تكرار كلاسيكية.

Divide

قسّم المصفوفة إلى نصفين.

Conquer

رتّب كل نصف تكراريًا.

Combine

ادمج النتائج بزمن O(n).

6.12 طريقة شجرة الاستدعاء

تُصوِّر شجرة الاستدعاء التكلفة عند كل مستوى من الاستدعاء-الذاتي، مما يجعل التعقيد الكلي بديهيًا. انظر الشجرة الكاملة أدناه في قسم الرسومات.

قراءة الشجرة: كل مستوى يكلّف n بالضبط · عدد المستويات: log₂ n · التكلفة الكلية: n × log n.

النتيجة: T(n) = O(n log n) — تُظهر شجرة الاستدعاء بالضبط من أين يأتي التعقيد — كل مستوى يُسهم بالتساوي.

6.13 طريقة الاستبدال

تُثبت حدًا مقاربًا عبر عملية من ثلاث خطوات: تخمين ← استبدال ← إثبات.

مثال: T(n) = T(n/2) + 1. نُخمّن T(n) = O(log n). نفترض T(n/2) ≤ c log₂(n/2) + d، نستبدل لنحصل على T(n) ≤ c log₂(n/2) + d + 1. بما أن log₂(n/2) = log₂ n − 1، يصمد الحد لـc مناسبة.

6.14 نظرية Master

اختصار قوي لحلّ علاقات تكرار خوارزميات فرّق تسد — بلا حاجة للتوسيع خطوة بخطوة.

General Form:        T(n) = aT(n/b) + f(n)
Example — Merge Sort: T(n) = 2T(n/2) + n
الرمزالمعنىقيمة Merge Sort
aعدد المسائل الفرعيةa = 2 — مسألتان فرعيتان
n/bحجم كل مسألة فرعيةb = 2 — كل منها نصف الحجم
f(n)العمل خارج الاستدعاء-الذاتيf(n) = n — تكلفة الدمج
نظرية Master اختصار، وليست بديلًا عن الفهم.

6.15 حالات نظرية Master الثلاث

لـT(n) = aT(n/b) + f(n)، قارن f(n) بـn^(log_b a).

الحالةالشرطالنتيجة
الحالة 1 — التكرار-الذاتي يُهيمنf(n) = O(n^(log_b a − ε))T(n) = Θ(n^(log_b a))
الحالة 2 — متوازنf(n) = Θ(n^(log_b a))T(n) = Θ(n^(log_b a) log n)
الحالة 3 — غير التكراري-الذاتي يُهيمنf(n) = Ω(n^(log_b a + ε)) وشرط الانتظام يصمدT(n) = Θ(f(n))
الاستراتيجية: Calculate → Compare → Classify → Solve

6.16 تطبيق نظرية Master: Binary Search

T(n) = T(n/2) + 1
الخطوةالقيمة
المُعاملاتa = 1, b = 2 — مسألة فرعية واحدة، نصف الحجم
f(n)f(n) = 1 — عمل مقارنة ثابت
n^(log_b a)n^(log₂ 1) = n⁰ = 1 — يُطابق f(n) ← الحالة 2

الطرق الثلاث في نظرة واحدة: علاقات التكرار تُشكّل التكلفة التكرارية-الذاتية؛ شجرة الاستدعاء تُصوّر العمل لكل مستوى؛ نظرية Master تُصنِّف في 3 حالات.

6.17 متى لا تنطبق نظرية Master

تنطبق نظرية Master فقط على T(n) = aT(n/b) + f(n). تحقّق من الصيغة أولًا.

الحالةمثاللماذا تفشل
إنقاص ثابتT(n) = T(n−1) + nيتناقص الحجم بثابت، لا بكسر.
مسائل فرعية غير متساويةT(n) = T(n/2) + T(n/3) + nيجب أن تتشارك المسائل الفرعية نفس القاسم b.
ليست فرّق تسدأي صيغة خارج نموذج فرّق تسدعلاقات التكرار خارج نموذج فرّق تسد لا تُناسب.

6.18 التعرّف على أنماط علاقات التكرار

بنية علاقة التكرار تكشف تعقيدها. اسأل: كيف يتغيّر n؟ كم استدعاءً تكراريًا-ذاتيًا؟ كم العمل لكل مستوى؟

علاقة التكرارالنمط الأساسيالتعقيد
T(n) = T(n/2) + 1القسمة على 2Θ(log n)
T(n) = T(n − 1) + 1الإنقاص بواحدΘ(n)
T(n) = 2T(n/2) + nنصفان + عمل خطيΘ(n log n)
فكرة أساسية: n/2 ← عمق لوغاريتمي. n−1 ← عمق خطي. استدعاءات تكرارية-ذاتية أكثر ← عمل كلي أكثر.

6.19 تحدي نظرية Master (مثالان محلولان)

حدّد a وb وf(n) — ثم قارن f(n) بـn^(log_b a) لاختيار الحالة.

التحدي 1 — الحالة 2 
T(n) = 4T(n/2) + n²

a = 4, b = 2, f(n) = n²

n^(log₂4) = n² = f(n)

النتيجة: T(n) = Θ(n² log n)
التحدي 2 — الحالة 3 
T(n) = 4T(n/2) + n³

n³ تنمو أسرع من n^(log₂4) = n².

شرط الانتظام يصمد.

النتيجة: T(n) = Θ(n³)
استراتيجية امتحان: a → b → f(n) → Compare → Case → Result

🌳 مخطط 2 — شجرة استدعاء Merge Sort (شريحة 13)

Recursion Tree

شجرة ثنائية جذرها موسوم "n" (المسألة الكاملة)، وكل مستوى أسفله ينقسم لعقدتين نصف الحجم: n/2 وn/2 عند المستوى 1، n/4 (×4) عند المستوى 2، وهكذا حتى أوراق بحجم 1. بجانب الشجرة، مجموع جارٍ يُظهر أن تكلفة كل مستوى مجتمعة هي n بالضبط — لأنه رغم أن كل عقدة نصف حجم أصلها، يوجد ضعف عدد العقد، فيبقى المجموع لكل مستوى ثابتًا عند n حتى الأسفل.

Level 0 (1 node):     [ n ]                      cost = n
                        /      \
Level 1 (2 nodes):  [n/2]    [n/2]                 cost = n/2 + n/2 = n
                    /   \      /   \
Level 2 (4 nodes): [n/4][n/4][n/4][n/4]             cost = 4×(n/4) = n
                     ...                 ...
Level log₂n:       [1][1][1][1] ... [1][1]          cost = n×1 = n

Number of levels: log₂ n
Total cost: n × log₂ n  →  T(n) = O(n log n)

تبسيط على 3 مستويات

تخيّل علاقة التكرار مثل وصفة تستدعي نفسها:

  • "لتخبز هذه الكعكة، اخبز أولًا كعكة نصف الحجم (هذا الجزء التكراري-الذاتي)، ثم اقضِ وقتًا قليلًا لتزيينها (هذا العمل الخارجي)، وإذا كانت الكعكة بحجم قضمة أصلًا، كُلها فقط — لا تخبز أكثر (هذه الحالة الأساسية)."
  • شجرة الاستدعاء مثل رسم كل "نصف كعكة داخل نصف كعكة" حتى تصل لقطع بحجم قضمة، ثم جمع كل وقت التزيين عبر كل الطبقات.
  • Big O مثل قول "سأنتهي خلال ساعة على الأكثر" (سقف آمن)؛ Big Theta مثل قول "سأنتهي خلال 45 دقيقة بالضبط" (الحقيقة الدقيقة).
  • نظرية Master جدول بحث جاهز: بمجرد معرفة كم كعكة مصغرة تخبز وكم حجمها، لست مضطرًا لرسم الشجرة كاملة — تتحقق فقط من "الحالة" التي أنت فيها.

تُصيغ علاقة التكرار التكلفة التكرارية-الذاتية رسميًا كـT(n) = [استدعاءات تكرارية-ذاتية] + [عمل خارجي]، مُرتكِزة على حالة أساسية T(1) = c. ثلاث أدوات مستقلة تحلّها. التوسيع يفكّ علاقة التكرار مستوى بمستوى حتى الوصول للحالة الأساسية، يعدّ عدد المستويات k (الذي يعتمد على سرعة تناقص n — القسمة تُعطي k = log_b n، والطرح يُعطي k = n)، ويجمع العمل الخارجي عبر كل المستويات k. أما الاستبدال فيُخمّن صيغة الإجابة المقاربة مُسبقًا، يُدخل هذا التخمين في علاقة التكرار مستوى أدنى، ويُظهر جبريًا أن التخمين يبقى متّسقًا — هذا يُثبت حدًا بدلًا من اشتقاقه، ولهذا يتطلب تخمينًا بدئيًا معقولًا.

نظرية Master اختصار بصيغة مُغلَقة خاص بشكل فرّق تسد T(n) = aT(n/b) + f(n): يستبدل الجمع مستوى بمستوى لشجرة الاستدعاء بمقارنة واحدة بين f(n) (العمل غير التكراري-الذاتي) وn^(log_b a) (ما ستُكلّفه المسائل الفرعية وحدها). عندما يُهيمن الجزء التكراري-الذاتي (الحالة 1)، تفوز التكلفة التكرارية-الذاتية؛ عندما يتساويان (الحالة 2)، يأتي عامل log n من جمع المساهمات المتساوية عبر log n مستوى — تمامًا ما أظهرته شجرة الاستدعاء لـMerge Sort؛ عندما يُهيمن f(n) (الحالة 3)، يطغى عمل المستوى الأعلى على كل ما تحته، رهنًا بشرط انتظام يمنع سلوك f(n) الشاذ. شرط النظرية المسبق — الصيغة بالضبط aT(n/b) + f(n) بقاسم ثابت b مشترك عبر مسائل فرعية متساوية الحجم — هو أيضًا حدودها: علاقات التكرار الطرحية، أو أحجام المسائل الفرعية غير المتساوية، أو البنى غير فرّق تسد تقع خارجها تمامًا وتحتاج التوسيع أو الاستبدال بدلًا منها.

  • Recurrence = T(n) = [recursive part] + [outside work], base case T(1)=c.
  • Binary Search: T(n) = T(n/2) + c -> Theta(log n).
  • Merge Sort: T(n) = 2T(n/2) + n -> Theta(n log n).
  • Expansion: unroll level by level, find k levels, sum work.
  • Substitution: Guess -> Substitute -> Prove by induction.
  • Dominant term: largest-growing term as n -> infinity; constants/lower terms ignored.
  • Big O = upper bound (ceiling, maybe not tight). Big Theta = tight bound (exact).
  • Growth order: log n < n < n log n < n^2 < n^3 < 2^n.
  • Recursion tree: levels x cost-per-level = total. Merge Sort: log n levels x n = n log n.
  • Master Theorem: T(n) = aT(n/b) + f(n). Compare f(n) to n^(log_b a).
  • Case 1 (recursive dominates): T(n)=Theta(n^(log_b a)). Case 2 (balanced): x log n. Case 3 (f(n) dominates + regularity): Theta(f(n)).
  • Master Theorem does NOT apply to: T(n-1)+n, T(n/2)+T(n/3)+n, or non-D&C recurrences.
  • Challenge: T(n)=4T(n/2)+n^2 -> Case 2 -> Theta(n^2 log n). T(n)=4T(n/2)+n^3 -> Case 3 -> Theta(n^3).

🔍
اكتب دائمًا علاقة التكرار مباشرة من بنية الخوارزمية: عُدّ كم استدعاءً تكراريًا-ذاتيًا، وكم يصغر كل مدخل، وما العمل غير التكراري-الذاتي عند كل استدعاء — هذه الأشياء الثلاثة هي علاقة التكرار نفسها.
✍️
لنظرية Master، احسب دائمًا n^(log_b a) أولًا، ثم قارنه بـf(n) — محاولة تخمين الحالة قبل هذه المقارنة هي أكثر مصدر شائع للأخطاء.
📐
اربط ترتيب معدلات النمو بقصة تتذكرها فورًا: log n بالكاد تنمو، n تنمو بثبات، n² وn³ تنفجران، وفي النهاية 2ⁿ تتفوق على الجميع.

🏋️ تدريب عملي مقترح

1️⃣
اشتق T(n) = T(n/2) + c لـBinary Search بالتوسيع بنفسك على ورقة، بكتابة المستويات من 1 إلى 4 قبل القفز للصيغة العامة لمستوى k.
2️⃣
ارسم شجرة استدعاء Merge Sort الكاملة لـn مُحدَّدة (مثل n=16)، مُسمِّيًا عدد العقد وحجمها ومجموع كل مستوى.
3️⃣
صنِّف 5 علاقات تكرار مُخترَعة جديدة بصيغة aT(n/b)+f(n) باستخدام نظرية Master، ثم تحقق من كل منها مقابل قائمة "متى لا تنطبق" لتتدرّب على رصد الصيغ غير الصالحة أيضًا.

⚠️ أخطاء شائعة يقع فيها الطلاب في هذا الموضوع تحديدًا

❌
معاملة Big O وBig Theta كأنهما قابلان للتبادل: n = O(n²) عبارة صحيحة لكنها فضفاضة؛ n = Θ(n²) خاطئة لأن Θ تتطلب نفس معدل النمو، وليس مجرد سقف أعلى. أعطِ دائمًا أدقّ حد يمكنك تبريره.
❌
تطبيق نظرية Master على أي معادلة تبدو تكرارية-ذاتية: تعمل فقط للصيغة بالضبط T(n) = aT(n/b) + f(n) بقاسم ثابت b مشترك بين مسائل فرعية متساوية الحجم. T(n) = T(n−1) + n وT(n) = T(n/2) + T(n/3) + n كلاهما يقع خارجها.
❌
نسيان حساب n^(log_b a) قبل المقارنة: لا يمكنك اختيار حالة نظرية Master "بالحدس" — احسب دائمًا هذه القيمة صراحةً أولًا، ثم قارنها بـf(n).
❌
الخلط بين إنقاص "n − 1" وقسمة "n / 2" من ناحية معدل النمو: الطرح بواحد كل مرة يُعطي n مستوى (عمق خطي)؛ القسمة على 2 كل مرة تُعطي log₂ n مستوى (عمق لوغاريتمي) — فرق عملي هائل.
