SLIDE 01

Data Mining — Chapter 4 — OLAP

غلاف المحاضرة يحدد الجزء الخاص بـ OLAP داخل Data Mining.

ما الفكرة؟

OLAP تعني Online Analytical Processing، أي معالجة تحليلية تفاعلية للبيانات. لا نستخدمها لتسجيل كل عملية بيع لحظيًا، بل لتحليل تاريخي متعدد الأبعاد يساعد الإدارة في اتخاذ القرار.

احفظ العلاقة: Data Mining يبحث عن patterns، بينما OLAP يتيح الاستعلام والتحليل والتقارير على مستودع البيانات.

Technical reading

The title places OLAP inside the broader Data Mining and Data Warehousing context.

للمراجعة: OLAP = analysis and decision support, not routine transaction entry.
SLIDE 02

ما هو Data Warehouse؟

الشريحة تقدم تعريفات متعددة، ثم تعريف Inmon الشهير، وتفرق بين المستودع وقاعدة البيانات التشغيلية.

التعريف خطوة بخطوة

Data Warehouse هو قاعدة بيانات مخصصة لدعم القرار، تُحفظ منفصلة عن Operational Database. السبب هو أن التحليل التاريخي الثقيل قد يبطئ المعاملات اليومية إذا أُجري على نفس النظام.

التعريف الرسمي: Subject-oriented, Integrated, Time-variant, Nonvolatile. أي أنه منظم حول موضوعات، يدمج مصادر متعددة، يحتفظ بالزمن والتاريخ، ولا يتغير مع كل معاملة تشغيلية.

Data warehousing هو عملية بناء واستخدام Data Warehouses، وليس اسم قاعدة البيانات فقط.

Technical reading

A separate, historical, consolidated platform for management decision-making.

للمراجعة: Remember the four adjectives: subject-oriented, integrated, time-variant, nonvolatile.
SLIDE 03

Data Warehouse — Subject-Oriented

المستودع يدور حول موضوعات الأعمال الرئيسية، لا حول تفاصيل تنفيذ المعاملات اليومية.

كيف نعرف أنه Subject-Oriented؟

  • نختار موضوعًا مثل Customer أو Product أو Sales.
  • نركز على أسئلة القرار والتحليل المتعلقة بالموضوع.
  • نستبعد البيانات التي لا تساعد في Decision Support.

مثال: النظام التشغيلي يسجل “تم بيع المنتج X عند الساعة 10:03”. المستودع يتيح سؤالًا مثل “ما اتجاه مبيعات فئة المنتجات X في كل فرع خلال خمس سنوات؟”

Technical reading

Subject-oriented means analysis is centered on business subjects and concise decision views.

للمراجعة: Do not confuse subject-oriented modeling with process-oriented transaction recording.
SLIDE 04

Data Warehouse — Integrated

التكامل يعني جمع مصادر مختلفة وغير متجانسة وتحويلها إلى تمثيل متسق داخل المستودع.

لماذا نحتاج Data Cleaning وData Integration؟

المصادر قد تكون Relational Databases أو Flat Files أو Online Transaction Records. قد يكتب مصدرٌ السعر بالدولار وآخر بالجنيه، أو يشمل الضريبة/الإفطار وآخر لا يشملهما.

قبل التحميل يجب توحيد Naming Conventions وEncoding Structures وAttribute Measures. عند نقل البيانات إلى Warehouse تُحوّل إلى الصيغة المتفق عليها.

مثال الفندق: “السعر 100” بلا تحديد العملة والضريبة ليس قيمة قابلة للمقارنة حتى نعرف قواعد التحويل.

Technical reading

Integration is about consistency across sources, not just copying tables.

للمراجعة: Cleaning and integration resolve semantic and format conflicts before analysis.
SLIDE 05

Data Warehouse — Time-Variant

المستودع يحتفظ بمنظور تاريخي أطول بكثير من Operational Database.

الفرق الزمني

Operational Database غالبًا يعرض Current Value Data: السعر أو الرصيد الحالي. أما Warehouse فيحتفظ بتاريخ، مثل آخر 5–10 سنوات، حتى نحلل الاتجاهات والمقارنات.

كل Key Structure في المستودع يحتوي عنصر Time صراحة أو ضمنيًا. في البيانات التشغيلية قد لا يتضمن المفتاح الزمن أصلًا.

إذا تغير سعر المنتج، لا نمسح السعر القديم في التحليل التاريخي؛ نحتاج معرفة ماذا كان السعر في فترة معينة.

Technical reading

Historical time is part of the warehouse model.

للمراجعة: Time-variant enables “as-of” and trend questions.
SLIDE 06

Data Warehouse — Nonvolatile

المستودع مخزن منفصل تُحمّل إليه البيانات، ولا تحدث فيه Operational Updates المعتادة.

ما معنى Nonvolatile؟

لا يعني أن البيانات لا تُحدّث أبدًا؛ المقصود أن المستخدمين لا ينفذون عليها تحديثات تشغيلية لحظية مثل INSERT/UPDATE لكل معاملة. تأتي البيانات عبر Initial Loading ثم Refresh مضبوط.

لذلك لا يحتاج المستودع بنفس الدرجة إلى Transaction Processing وRecovery وConcurrency Control الخاصة بالأنظمة التشغيلية. عمليتا الوصول الأساسيتان هما Initial Loading وData Access.

Technical reading

Nonvolatile = stable analytical store, not a live transaction register.

للمراجعة: Do not interpret nonvolatile as “never refreshed”; refresh is explicitly part of the architecture.
SLIDE 07

OLTP vs. OLAP

هذه الشريحة تقارن بين النظام الذي يسجل المعاملات والنظام الذي يحلل البيانات.

الفكرة المقارنة

OLTP = Online Transaction Processing: معاملات قصيرة، بيانات حالية، عمليات إدخال وتعديل كثيرة، وعدد كبير من المستخدمين المتزامنين.

OLAP = Online Analytical Processing: استعلامات طويلة ومعقدة، قراءة وتجميع عبر تاريخ وم dimensions متعددة، وتقارير وData Mining.

OLTPOLAP
Current operational dataHistorical consolidated data
Insert/update transactionsRead, aggregate, analyze
Fast small transactionsComplex analytical queries

Technical reading

OLTP optimizes transaction throughput; OLAP optimizes analysis and decision support.

للمراجعة: The separate warehouse protects OLTP performance from analytical workloads.
SLIDE 08

Data Warehouse: A Multi-Tiered Architecture

المخطط يوضح طبقات تدفق البيانات من المصادر إلى التخزين ثم التحليل والأدوات الأمامية.

وصف الرسم بالتفصيل

في أقصى اليسار توجد Data Sources. تنتقل البيانات إلى Data Storage في الطبقة السفلية/الوسطى، حيث يوجد Data Warehouse وData Marts. Data Marts أجزاء أصغر موجهة لقسم أو موضوع محدد.

في الوسط يوجد Monitor & Integrator، وهو مسؤول عن مراقبة التدفق ودمج البيانات، ومعه Metadata التي تصف البيانات ومساراتها. يوجد OLAP Server/Engine فوق المستودع لتنفيذ التحليل متعدد الأبعاد.

في اليمين Front-End Tools مثل Analysis وQuery وReports وData Mining. أي أن المستخدم لا يتعامل عادةً مع مصادر التشغيل مباشرة، بل مع طبقة تحليلية منظمة.

Technical reading

Read the diagram left-to-right: sources → integration/metadata → warehouse/data marts → OLAP → front-end tools.

للمراجعة: The diagram is a pipeline plus governance: data movement, storage, analytical engine, and consumption.
SLIDE 09

Extraction, Transformation, and Loading (ETL)

ETL هو المسار العملي الذي يجعل البيانات جاهزة للمستودع، ثم تُضاف عملية Refresh للحفاظ على حداثتها.

مراحل ETL

01
Data extraction
سحب البيانات من مصادر متعددة وغير متجانسة وخارجية.
02
Data cleaning
اكتشاف الأخطاء وتصحيحها عندما يكون ذلك ممكنًا.
03
Data transformation
تحويل Legacy/Host Format إلى Warehouse Format.
04
Load + Refresh
ترتيب وتجميع وحساب Views وفحص Integrity وبناء Indices/Partitions ثم نشر التحديثات.

في Load لا ننسخ فقط: قد نعمل Sort وSummarize وConsolidate ونحسب Views ونفحص Integrity ونبني Indices وPartitions. Refresh ينشر التحديثات من المصادر إلى المستودع.

Technical reading

ETL transforms messy heterogeneous sources into governed warehouse-ready data.

للمراجعة: Cleaning is error correction; transformation is format/representation conversion; refresh is later propagation.
SLIDE 10

Metadata Repository

Metadata هي البيانات التي تصف Data Warehouse objects وتساعد على فهم البنية والمصدر والتاريخ والأداء وقواعد الأعمال.

ماذا يخزن Metadata Repository؟

  • وصف Structure: Schema وView وDimensions وHierarchies وDerived Data Definitions ومواقع ومحتويات Data Marts.
  • Operational Metadata: Data Lineage، Currency (Active/Archived/Purged)، Monitoring Information، Usage Statistics، Error Reports، Audit Trails.
  • Algorithms المستخدمة في Summarization.
  • Mapping من Operational Environment إلى Data Warehouse.
  • بيانات System Performance، مثل تعريفات Warehouse Schema وViews وDerived Data.
  • Business Data: المصطلحات والتعريفات وData Ownership وCharging Policies.

بدون Metadata يصبح المستودع مخزنًا كبيرًا بلا قاموس: قد نرى عمودًا ولا نعرف معناه أو مصدره أو متى أصبح Active.

Technical reading

Metadata answers: what is this data, where did it come from, how was it transformed, and who owns it?

للمراجعة: Metadata supports discoverability, governance, lineage, auditing, and correct interpretation.

05

التبسيط على 3 مستويات

01 · Beginner

تخيل متجرًا: OLTP يسجل كل عملية شراء، أما Data Warehouse فيحتفظ بتاريخ المبيعات ليسأل المدير: أي منتج يبيع أكثر في كل شهر؟ OLAP هو أداة طرح هذا السؤال وتحليل الإجابة.

02 · University

حلل أي مصطلح عبر: أين توجد البيانات؟ كيف دُمجت؟ هل لها تاريخ؟ كيف وصلت؟ ما Metadata التي تصفها؟ ثم حدد هل workload هو OLTP أم OLAP.

03 · Last-minute English

  • Warehouse = subject-oriented, integrated, time-variant, nonvolatile.
  • OLTP = current, short, write-heavy transactions.
  • OLAP = historical, complex, read/aggregate-heavy analysis.
  • ETL = extract, clean, transform, load; refresh later updates.
  • Metadata = structure, lineage, currency, performance, business meaning.
